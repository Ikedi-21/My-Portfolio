Methodology

How I Run Projects

I treat every project like a real product. Scoping requirements clearly, writing decisions down, and keeping communication open keeps engineering work on track.

The Delivery Lifecycle

Four project phases

From initial discovery through to live deployment.

01

Discovery & Scoping

Clarify core goals, define success criteria, and establish clear boundaries between what is in-scope and out-of-scope before writing code.

  • Stakeholder interview notes
  • User persona definitions
  • Acceptance criteria validation
02

Planning & Architecture

Write a product requirements document (PRD), design data models and system boundaries, and structure work into focused sprint backlogs.

  • Comprehensive PRD authoring
  • Entity relationship diagrams
  • Milestone and sprint breakdown
03

Build & Iterate

Develop in focused sprints with regular check-ins. Commit early, deploy frequently to staging, and review changes collaboratively.

  • Small Git commits with clear logs
  • Staging deployments
  • Code and boundary reviews
04

Delivery & Hand-off

Deploy production builds, verify DNS and security settings, write developer documentation, and support a smooth client handover.

  • Deployment runbooks and configs
  • Walkthroughs and handover documentation
  • Post-release retrospective review
Documentation

Artifacts I produce

Clear written documentation keeps the whole team aligned from kickoff to deployment.

Product Requirements Document (PRD)

The single source of truth outlining user personas, technical requirements, edge cases, and scope limits.

Architecture Decision Records (ADRs)

Short records detailing technical context, options considered, and reasons for choosing specific approaches.

Sprint Retrospectives

Brief reviews covering what worked, what caused friction, and what adjustments to make for the next sprint.
